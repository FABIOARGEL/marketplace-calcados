Apresentacao do Problema

Contexto, desafios e publico-alvo
02 / 18
Contexto

O comercio de calcados e um mercado relevante, mas vendedores independentes enfrentam dificuldade em alcancar clientes digitalmente sem uma plataforma integrada e acessivel.

Problema Central
📦

Vendedores: sem ferramenta unificada para cadastrar produtos, controlar estoque e acompanhar pedidos.

🔎

Compradores: dificuldade em encontrar, comparar e comprar de multiplos vendedores em um so lugar.

📊

Gestao: ausencia de visibilidade sobre pedidos, status de entrega e historico de compras.

Publico-Alvo
CLIENTES
  • ► Compradores de calcados online
  • ► Usuarios que buscam variedade
  • ► Clientes de multiplos vendedores
  • ► Foco em praticidade e seguranca
VENDEDORES
  • ► Lojistas e empreendedores
  • ► Vendas diretas ao consumidor
  • ► Gestao propria de produtos
  • ► Controle de pedidos e estoque
Solucao Proposta

Desenvolver um marketplace web integrado que conecta compradores e vendedores de calcados, com fluxo completo: catalogo → busca → carrinho → checkout → acompanhamento de pedidos.

🎯

Objetivos do Sistema

Objetivo geral e objetivos especificos

Objetivo Geral

Construir um marketplace web de calcados funcional, com dois perfis distintos de usuario, fluxo completo de e-commerce e gerenciamento de pedidos, desenvolvido com Python, Django e PostgreSQL.

Para o Cliente
🔒
Criar conta e autenticar-se por e-mail

Cadastro como cliente, login seguro e logout.

🔎
Pesquisar e filtrar calcados

Busca por nome, filtros por categoria, marca, tamanho e preco.

🛍
Gerenciar carrinho e finalizar compra

Adicionar, editar e remover itens. Checkout com frete simulado.

📦
Acompanhar pedidos

Historico detalhado com status, valores e endereco.

Para o Vendedor
➕
Cadastrar e gerenciar produtos

Criar calcados com imagens, preco e estoque por tamanho.

🗃
Controlar estoque por tamanho

Estoque individualizado. Soft delete para inativar produtos.

📋
Visualizar pedidos dos seus produtos

Dashboard exclusivo com pedidos que contem seus itens.

🚚
Atualizar status de entrega

Ciclo: PENDING → CONFIRMED → SHIPPED → DELIVERED.

Tecnologias e Ferramentas

Stack utilizada no desenvolvimento
05 / 18
🐍
Python 3.11+ & Django 4.2

Backend principal. Django LTS garante estabilidade. Padrao MVT sem API REST separada. Autenticacao por e-mail com EmailBackend customizado.

🐘
PostgreSQL 14+

Banco relacional robusto. Garante integridade com constraints, transacoes atomicas no checkout e tipagem correta (DecimalField para precos).

🔧
pgAdmin

Interface grafica para gerenciamento do PostgreSQL. Utilizado para inspecionar tabelas, executar queries e verificar integridade dos dados.

🐙
Git & GitHub

Versionamento e colaboracao. Estrategia: main → develop → feature/*. Pull Requests com code review entre os membros da equipe.

📋
Linear

Gerenciamento de tarefas e acompanhamento de sprints. Todas as atividades das 6 sprints foram registradas, distribuidas e monitoradas no Linear.

🎨
HTML + CSS Vanilla + JS

Frontend sem frameworks externos. Design System Neo-Brutalism com variaveis CSS, convencao BEM, sombras solidas e tipografia Space Grotesk + Inter.

Entrega
O que e uma Sprint?

Um ciclo de desenvolvimento com periodo e objetivo definidos. Cada sprint entrega funcionalidades de ponta a ponta: desde o backend ate o template funcional no browser.

Planejamento por Dependencias

Cada sprint foi planejada com base em analise de dependencias tecnicas (fatiamento vertical). Toda tarefa possui: objetivo, responsavel, Story Points, resultado esperado e DoD.

GitHub — Controle de Versao
  • ► Branch feature/nome por funcionalidade
  • ► Pull Request para develop com code review
  • ► Merge em main apos validacao final
  • ► Commits no padrao Conventional Commits
Linear — Gestao de Tarefas
  • ► Todas as 27 tarefas registradas por sprint
  • ► Atribuicao de responsavel e Story Points
  • ► Acompanhamento de progresso em tempo real
  • ► Status: To Do → In Progress → Done

Dificuldades e Aprendizados

Desafios enfrentados e crescimento da equipe
17 / 18
Principais Desafios
Integracao

Integrar codigo de diferentes integrantes exigiu disciplina com branches e revisao de Pull Requests para evitar conflitos.

Banco de dados

Modelagem do DER, relacoes entre apps e constraints do PostgreSQL (unique_together, DecimalField, transacoes atomicas).

Dependencias

Respeitar a ordem das sprints — nenhuma funcionalidade podia ser desenvolvida antes de sua dependencia estar pronta.

Tempo

Gerenciamento de tempo equilibrado entre as demandas academicas e as 118 Story Points das 6 sprints.

Testes

Criar testes automatizados significativos que cobrissem cenarios reais de erro, nao apenas o caminho feliz.

Aprendizados
Scrum

Planejamento por sprints com objetivos claros torna o desenvolvimento mais organizado e previsivel.

Git Flow

Branches por funcionalidade e Pull Requests garantem qualidade e rastreabilidade do codigo desenvolvido.

Django

O padrao MVT com autenticacao, ORM, forms e middleware facilita o desenvolvimento de sistemas web completos.

Arquitetura

Separar responsabilidades em apps independentes e respeitar camadas evita acoplamento e facilita a manutencao.

Equipe

Divisao clara de responsabilidades, comunicacao constante e revisao mutua foram fundamentais para a entrega.
